# 생활기록부 평가문(세특) 작성 스킬

학생 자료 → 통합 Excel → **학생별 구성 계획** → 평가문 작성(NLP) → 품질 보정·바이트 검증 → 검수 HTML·업로드 xlsx.
**평가문 문장은 전적으로 NLP(언어 능력)로 쓴다.** 스크립트는 바이트 계산, Excel/HTML 조립처럼 결정적인 일만 맡는다.

## 이 글의 목적 — 모든 규칙의 위에 있다
평가문은 **교사가 학생을 평가한 글**이다. 하는 일은 둘뿐이다.

  ① 이 학생이 **어떤 역량을 지닌 사람인지** 밝힌다.
  ② 그것을 **무엇으로 증명할 수 있는지** 보인다.

아래의 모든 규칙은 이 두 가지를 위해 있다. **규칙을 지키느라 이 목적이 흐려졌다면 규칙을 지킨 것이 아니다.**
활동 요약도, 형식 점검 통과도 목적이 아니다. 읽은 사람이 *"이 학생은 이런 사람이고, 근거는 이것이다"*라고
말할 수 있으면 좋은 평가문이고, 무슨 활동을 했는지만 남으면 실패한 평가문이다.

이 목적을 지키는 장치가 **4단계(구성 계획)**다. 자료를 읽자마자 문장부터 쓰면 글은 활동 보고가 되거나
규칙을 지키려 애쓴 글이 된다. **무엇을 증명할지 먼저 정하고 나서 쓴다.**

## 핵심 원칙
- **주장과 증명**: 글마다 증명할 주장이 하나 있고, 나머지 문장은 그 주장을 증명한다(→ 4단계).
- **NLP 작성**: 자료를 읽고 이해해 사람이 쓰듯 작성한다. "역량+근거"를 문자열 치환으로 조립하지 않는다.
- **자료에 충실**: 자료에서 실제로 확인되는 내용만 근거로 쓴다. 인터넷 검색·추측 금지. 학생 문장을 그대로 베끼지 않는다.
- **분량은 python으로 측정**: 바이트 규칙은 한글 3 / 엔터 2 / 그 외 1. 눈대중하지 말고 `scripts/byte_count.py`로 잰다.
- **쉼표·가운뎃점은 측정한다**: 연결어미(-고/-며/-여/-아/-어/-해) 뒤 쉼표와 가운뎃점(·) 나열은 세특에서 가장 잦은 AI 흔적이다. `scripts/comma_check.py`로 재서 **둘 다 0**으로 만든다(정리 후 바이트 재검증).
- **품질 보정**: 초안을 그대로 두지 않는다. `grammar-checker`(맞춤법·조사)·`humanizer`(번역투·명사화·획일적 결말)·`style-guide`(반 전체 용어·어조)로 다듬되, **세특의 명사형 종결·금지 주어·분량 규칙이 세 스킬의 기본값보다 우선**한다(→ `references/quality-skills/README.md`).
- **문장에 수치 상한을 두지 않는다**: 문장 수 제한, 첫 문장 길이 상한, "판단은 몇 번까지" 같은 세는 규칙은 두지 않는다. 지나친 제약이 이상한 문장을 만든다. 재는 것은 **전체 바이트**뿐이고, 나머지는 역할로 판단한다.
- **단계별 체크포인트**: 별도 지시가 없으면 6단계를 차례로 밟고, 각 단계 끝에서 결과를 보여주며 진행 여부를 확인한다.
- **과목별 MEMORY**: 시작 시 해당 과목의 누적 지시를 읽고, 새 지시가 나오면 저장한다.
- **스킬 스크립트는 공용 — 수정 금지**: `scripts/`는 모든 과목이 공유한다. 특정 과목에만 필요한 기능은 그 과목의 `results/<연도>_<과목>/`에 전용 변형 스크립트(예: `build_html_주목.py`)를 만들어 쓴다. 전용본은 파일 머리 주석에 어느 공용 스크립트의 변형인지 밝히고 공용 모듈은 sys.path로 import해 재사용한다. 공용 수정은 모든 과목에 이로운 범용 개선일 때만.

## 스킬 디렉토리
```
${CLAUDE_SKILL_DIR}/
├── SKILL.md
├── scripts/
│   ├── byte_count.py        # NEIS 바이트 계산(한글3/엔터2/그외1) · JSON 일괄 검수
│   ├── comma_check.py       # 연결어미 뒤 쉼표·가운뎃점 측정(필수) · --clean 정리
│   ├── build_workbook.py    # students.json → 통합 검수 .xlsx (활동별 열 + 계획 + 평가문 + 바이트/판정)
│   ├── build_html.py        # students.json → 표형 검수 HTML(정렬·검색·자료/계획 펼치기·평가문 복사)
│                            #   검토본이 있으면 원본과 나란히 + 바뀐 곳 변경 강조(diff)
│   ├── build_gwagi.py       # students.json → 업로드 xlsx. NEIS 다운로드 파일을 --template로 주면
│                            #   학생코드·수업코드 보존하며 세특 칸만 채움. --text로 판본 선택
│   ├── build_json.py        # students.json → 결과 JSON(평가문 산출물)
│   ├── evaltext.py          # 평가문·계획 필드 규약(평가문 / 평가문_검토본 / 계획). 빌드 스크립트 공용
│   ├── rawdata.py           # 원자료 규약 — students.json이 가리키는 `원자료.json`(활동지 원문·불변)을
│                            #   읽어 활동 원문을 이어 붙인다. 요약본을 복사해 두지 않기 위한 단일 기준
│   └── make_neis_sample.py  # build_gwagi.py의 NEIS 탐지/채우기 로직의 회귀 픽스처
├── assets/
│   ├── default_prompt.txt   # 기본 프롬프트 — 사용자 txt·과목 프롬프트가 없을 때 적응해 사용
│   └── 교과기초자료_양식.xlsx  # 교과세특 업로드 기준 양식(헤더: 학번·이름·교과세특·성적)
└── references/
    ├── memory/
    │   ├── INDEX.md          # 과목별 MEMORY 운영 규칙 + 목록
    │   └── <과목>.md          # 과목별 누적 지시(+ 맞춤 프롬프트 `prompts/<과목>.prompt.txt` 포인터)
    └── quality-skills/       # 평가문 품질 보정 스킬 번들 (5단계에서 사용)
        ├── README.md         # 통합 가이드 + 세특 가드레일(종결어미·분량이 스킬 기본값보다 우선)
        ├── grammar-checker/  # 맞춤법·띄어쓰기·조사·구두점 교정
        ├── humanizer/        # AI 흔적 제거: 쉼표 과다·번역투·명사화·결말 공식 등 40패턴
        └── style-guide/      # 반 전체 일관성: 용어·어조·구두점
```
경로 참조 시 `${CLAUDE_SKILL_DIR}`는 이 SKILL.md가 들어 있는 스킬 폴더다.

## 작업 폴더 구조 (스킬 밖 · 현재 작업 디렉토리 기준)
과목 맞춤 프롬프트와 모든 산출물은 스킬 폴더가 아니라 **작업 폴더** 아래에 둔다.
```
작업폴더/
├── prompts/
│   └── <과목>.prompt.txt          # 과목 맞춤 프롬프트(2단계에서 저장·재사용)
└── results/
    └── <연도>_<과목>/              # 과목 폴더 (예: results/2026_정보/)
        ├── README.md              # 판본 이력 — 어느 폴더가 최종인지 여기 적는다
        ├── 원자료.json             # 학생 활동지 원문(판본과 무관·불변)
        ├── 공용/                   # 판본과 무관한 도구(extract_raw.py 등)
        └── <판본>/                 # ★ 판본 한 벌 — v1·v2… 또는 codex·fable 같은 변형
            ├── students.json      #   중간 데이터(3단계 생성 → 4단계 계획 → 5단계 평가문)
            ├── 결과.xlsx / 결과.html  # 검수용
            ├── 교과기초자료.xlsx    #   교과세특 업로드 양식(최종 산출)
            └── 작업/               #   그 판본을 만들 때 쓴 스크립트·중간 파일
```
- `prompts/`·`results/`는 **작업 폴더 기준 상대경로**다. 스킬 폴더 안에는 산출물을 쓰지 않는다.
- 과목 **누적 지시**(`references/memory/<과목>.md`)만 스킬 안에 남고, **프롬프트 본문**은 작업 폴더에 둔다.
- **판본은 폴더로 가른다.** 같은 과목을 다시 쓸 때마다 `v6/`처럼 새 폴더를 만들고 **그 안의 파일 이름은 늘 같게** 둔다.
  파일명에 `_v6` 접미사를 붙이지 않는다 — 한 폴더에 접미사만 다른 파일이 수십 개 쌓이면 어느 것이 한 벌인지 알 수 없다.
  (이미 그렇게 쌓인 폴더는 `tools/organize_versions.py`가 판본별로 갈라 준다. `--dry`로 확인하고 `--undo`로 되돌린다.)
- **`원자료.json`은 판본 위에 둔다.** 자료는 판본이 바뀌어도 그대로이므로 과목 폴더 바로 아래 두고,
  각 판본의 `students.json`이 `"원자료": "../원자료.json"`으로 가리킨다.

## 자료 형식: `원자료.json`(불변) + `students.json`(작업 파일)
**활동 자료는 요약하지 않는다.** 3단계에서 원본을 그대로 담은 `원자료.json`을 한 번 만들고, 이후 모든 단계는
그 원문을 근거로 삼는다. `students.json`은 자료를 복사해 두지 않고 파일을 가리키기만 한다.

```json
// 원자료.json — 활동지 원문. 한 번 뽑으면 바뀌지 않는다(여러 판본이 함께 참조).
{ "subject": "프로그래밍", "출처": ["2026 프로그래밍 활동지.xlsx"],
  "활동명": {"프로그래밍 3차시": "자기소개 웹페이지 만들기", "…": "…"},   // 시트 → 공식 활동명
  "students": [ {"학번": "20109", "이름": "홍길동",
                 "제출": {"프로그래밍 3차시": [ {"제출시각": "…", "HTML 코드": "…원문…"} ]}} ],
  "미매칭": [] }
```
- **요약본을 근거로 쓰지 않는 이유**: 요약은 누가 언제 정리했느냐에 따라 달라지고, 원문에만 있는 판단의 흔적이 사라진다. 실제로 요약본만 보고 쓴 판본에서 **인공지능이 대신 써 준 문장을 학생의 서술로 오인**하거나 **제출 시각을 놓쳐 사실을 잘못 단정**한 사례가 나왔다.
- **중복 제출·오기도 버리지 않는다.** 제출 순서대로 모두 담고, 최신본 선택은 쓰는 쪽에서 판단한다. 학생 식별이 실패한 행은 `미매칭`에 남겨 사람이 확인한다.
- **코드 제출물**은 코드를 그대로 담되, 평가문에는 코드를 옮기지 않고 **구조를 세어 근거로 삼는다**(과목 폴더의 읽기 도우미가 태그·CSS·JS 요소를 계수해 보여준다).
- 빌드 스크립트는 `scripts/rawdata.py`로 이 파일을 자동으로 이어 붙여 검수 산출물에 원문을 싣는다.

### `students.json` — 판본마다 바뀌는 작업 파일
3단계에서 만들고, 4단계에서 `계획`을, 5단계에서 `평가문`을 채운다. `"원자료"`로 원문 파일을 가리킨다.
```json
{
  "subject": "인공지능 기초",
  "원자료": "원자료.json",
  "students": [
    {
      "번호": "10101", "이름": "홍길동", "성적": 92,
      "제약사항": "장기결석으로 서비스개발 보고서 없음",
      "목표바이트": "1400~1500",
      "계획": {
        "주장": "무엇을 할 줄 아는 사람인지 한 문장",
        "근거": [{"활동": "이미지분류프로젝트", "사실": "…", "증명": "이 사실이 주장을 뒷받침하는 이유"}],
        "순서": "이미지분류 → 자기평가. 앞의 판단이 뒤의 성찰로 이어지므로",
        "제외": "정확도 수치 비교 — 주장과 무관"
      },
      "평가문": "",
      "바이트수": 0,
      "평가문_검토본": ""
    }
  ]
}
```
- `활동`의 키(=활동명)는 자유롭게 늘릴 수 있고, Excel에서 그대로 열이 된다.
- **`계획`은 4단계 산출물**이다. 5단계는 이 계획을 문장으로 옮기는 일이며, 계획과 다르게 쓰게 되면 계획을 고친다.
- **`평가문_검토본`은 5.5 검토 패스를 돌렸을 때만 생긴다.** 검토 결과는 `평가문`을 **덮어쓰지 않고** 이 필드로 **추가**한다(규약: `scripts/evaltext.py`).
- `목표바이트`는 프롬프트의 분량 규칙 + 성적/자료 밀도로 정한다(스크립트가 강제하지 않는다).

## 1단계 — 기초 정보 수집 (+ 과목 MEMORY 로드)
꼭 필요한 것만 간단히 묻는다. 이미 답이 주어졌으면 다시 묻지 않는다.
1. **과목명** (예: 인공지능 기초, 정보, 프로그래밍)
2. **제공 자료**: 종류와 경로. ① 이미 정리된 CSV/Excel인지 ② 학생별 개별 파일(pdf/hwpx/xlsx)인지.
3. **프롬프트**: 사용자 txt 경로가 있는지. 없으면 `assets/default_prompt.txt`를 적응해 쓴다고 안내.
4. **성적/제약사항** 자료가 따로 있는지(분량 조절·자료 누락 처리에 쓰임).
5. **NEIS 업로드 양식**(권장): NEIS에서 내려받은 엑셀이 있으면 6단계에서 그대로 채워 바로 업로드할 수 있다. 경로를 받으면 `<과목>.md`에 적어 둔다.
6. **대상 연도(학년도)** — 산출물 폴더명 `results/<연도>_<과목>/`에 쓴다.

그다음 `references/memory/<과목>.md`와 `prompts/<과목>.prompt.txt`(있으면)를 읽어 이후 단계에 반영한다.
정리한 기초 정보를 한 번 요약해 보여주고 넘어간다.

## 2단계 — 프롬프트 준비 (사용자 txt → 과목 저장 프롬프트 → 기본 프롬프트 적응)
출처를 다음 **우선순위**로 정한다.
1. **사용자가 txt 경로를 준 경우** → 그 파일을 읽어 사용한다(계속 쓸 양식이면 `prompts/<과목>.prompt.txt`로 저장).
2. **`prompts/<과목>.prompt.txt`가 있으면** → 그대로 사용한다(매번 다시 만들지 않는다).
3. **둘 다 없으면** → `assets/default_prompt.txt`를 1단계 정보에 맞게 **적응**해 저장한다. 기본 프롬프트에 비어 있는 세 칸을 반드시 채운다.
   - **사용할 학생 자료** — 사용자가 실제로 제공한 자료.
   - **활동명 목록** — 평가문은 근거가 어느 활동에서 나왔는지 밝혀야 한다. **원자료의 공식 명칭**(자기평가서의 활동 선택지, 활동지 제목, 시트명, 차시 계획)을 찾아 쓰고 임의로 짓지 않는다. 표기에 가운뎃점·특수기호가 있으면 평가문 표기 규칙에 맞게 고쳐 고정한다. 찾지 못하면 이름을 제안하고 **사용자에게 확인받는다.**
   - **근거의 우선순위** — 같은 사실이 여러 자료에 겹칠 때 무게중심을 어디에 둘지의 기준. **학생 본인이 쓴 성찰 자료(자기평가서 등)를 1순위로 두는 것이 기본**이고, 그 자료가 없는 학생은 다음 순위가 1순위가 된다는 점을 함께 적는다.
   - 과목명·분량 규칙(성적 또는 자료 밀도 연동)을 실제 기준으로 바꾼다.
   - **핵심 규칙은 유지한다**: 사실 근거 / 원문 복붙 금지 / 활동명 표기 / 알맹이 서술과 구현 디테일 금지 / 명사형 종결 / 금지 주어 / 부정·예측 평가 금지 / 개인정보·실명·기업명·교외 수상 금지 / 도서명·작가명 정확 표기 / 미입증 근거 금지 / 연결어미 뒤 쉼표·가운뎃점 0. 과목에 맞게 **표현을 적응하거나 규칙을 더하는 것은 되지만 위 항목을 없애지는 않는다.**
   - 반대로 **과목에 필요 없는 세부 제약은 덜어낸다.** 규칙이 많을수록 좋은 글이 나오는 것이 아니다. 규칙은 목적(역량과 증명)을 돕는 만큼만 둔다.
   - 적응한 프롬프트를 사용자에게 보여 확인받고 `prompts/<과목>.prompt.txt`로 저장한다.

어느 경로든, 쓸 프롬프트에서 **추출**할 것을 요약해 확인받는다: ① 평가 관점/역량 분류 ② 분량 규칙 ③ 문체·어미 ④ 금지사항 ⑤ 사용할 자료·활동명.
**이번 프롬프트의 규칙을 그대로 따른다**(스킬에 박힌 가정으로 덮어쓰지 않는다).

## 3단계 — 학생 자료 처리 → 원자료.json + students.json
**요약하지 말고 원문을 담는다.** 흩어진 자료에서 **셀·문단 값을 그대로** 옮겨 `원자료.json`을 만들고,
`students.json`은 학생 명단과 제약사항만 담아 그 파일을 가리킨다.

- **추출 스크립트를 과목 폴더에 만든다**(`results/<연도>_<과목>/extract_raw.py`). 원본이 바뀌면 다시 돌리면 되고, 바뀌지 않으면 다시 돌릴 일이 없다. 공용 스크립트는 원본 형식이 과목마다 달라 두지 않는다.
- **pdf**는 `Read`로, **hwpx/hwp**는 `hwpx` 스킬로, **xlsx**는 `openpyxl`/`xlsx` 스킬로 원문을 뽑는다. **여기서 요약하지 않는다** — 무엇을 근거로 삼을지는 4단계의 판단이다.
- 학생 식별 규칙(학번·반/번호·이름)과 이름 오기·별칭은 추출 스크립트에 적어 두고, **미매칭은 0이 될 때까지** 맞춘다.
- 자료가 없는 항목은 `제약사항`에 남긴다(원자료의 제출 목록과 대조해 자동으로 적을 수 있다).
- 원자료 밖의 정보(교사 관찰 등)는 `제약사항`에 출처를 밝혀 적는다.

```bash
python results/<연도>_<과목>/extract_raw.py     # → 원자료.json (+ 미매칭 리포트)
python "${CLAUDE_SKILL_DIR}/scripts/build_workbook.py" results/<연도>_<과목>/<판본>/students.json results/<연도>_<과목>/<판본>/결과.xlsx
```

```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_workbook.py" results/<연도>_<과목>/<판본>/students.json results/<연도>_<과목>/<판본>/결과.xlsx
```
Excel을 보여주고 "자료 정리가 맞는지" 확인받은 뒤 4단계로 간다. **이 시점에 계획·평가문 열은 비어 있다.**

> 자료 추출은 학생 수가 많으면 나눠서 해도 되지만 **추출(사실 정리)과 작성(NLP 서술)은 분리**한다.

## 4단계 — 학생별 구성 계획 (쓰기 전에 설계한다)
**이 단계가 이 스킬의 방향타다.** 자료를 읽자마자 문장부터 쓰면, 글은 활동을 시간순으로 옮긴 보고서가 되거나
규칙 목록을 하나씩 통과시키는 글이 된다. 어느 쪽도 *"어떤 역량을 지닌 학생인가"*에 답하지 않는다.

학생 한 명마다 아래 넷을 **짧게** 적는다. 완성된 문장이 아니라 설계 메모다.

**원문을 읽고 세운다(필수).** 계획은 `원자료.json`의 원문을 직접 읽고 세운다. 앞 판본의 계획이나 누군가 정리해 둔
요약을 근거로 삼지 않는다. 원문에서만 드러나는 것들이 있다.
  · **누가 쓴 글인지** — 제출 칸에 인공지능 대화 로그나 인공지능이 대신 써 준 문장을 붙여 넣은 학생이 있다. 학생이 직접 쓴 칸에서만 근거를 뽑는다.
  · **언제 낸 것인지** — 제출 시각을 보아야 '수업보다 앞서 만든 것'인지 '나중에 다시 손본 것'인지 갈린다.
  · **실제로 만든 것** — 코드 제출물은 구조를 세어야 무엇을 만들었는지 확인된다.

1. **주장** — 이 학생은 무엇을 할 줄 아는 사람인가. 자료 전체를 읽고 내린 교사의 판단 **한 문장**.
   - 역량 이름표(`문제해결력`·`창의적 사고`)를 붙이는 자리가 아니다. **무엇을 어떻게 하는 힘인지 내용으로** 적는다.
     (`안 되는 원인을 화면이 아니라 처리 순서에서 찾는다`처럼)
   - 이 주장이 글 전체가 증명할 명제다. **첫 문장은 이 주장을 서론으로 옮긴 것**이고, 맺음말을 쓴다면 여기로 돌아온다.
2. **증명** — 그 주장을 무엇으로 증명하는가. 근거를 1~2개 고르고, 근거마다 세 가지를 적는다.
   `어느 활동의 / 어떤 사실이 / 왜 그 주장을 뒷받침하는지`
   - **'왜 뒷받침하는지'를 한 줄로 적지 못하는 근거는 쓰지 않는다.** 글이 산만해지는 원인은 대개 근거가 부족해서가 아니라 주장과 무관한 근거가 섞여서다.
   - 근거는 자료에 실제로 있는 사실이어야 한다. 없으면 주장을 자료에 맞게 낮춘다(주장에 맞춰 사실을 부풀리지 않는다).
3. **순서** — 근거를 어떤 순서로 놓아야 읽는 사람이 그 주장에 이르는가. **활동 단위로 묶고**, 활동 안에서는 일이 진행된 순서(문제 인식 → 판단 → 부딪힌 문제 → 해결 → 남은 과제). 활동 사이를 오가지 않는다.
4. **제외** — 자료에 있으나 **쓰지 않을 것**과 그 이유. 분량을 채우려고 남은 사실을 밀어 넣으면 논지가 흐려진다. 무엇을 버릴지 미리 정해 두면 5단계에서 흔들리지 않는다.

**반 전체 점검(중요)**: 계획을 다 세운 뒤 **주장만 모아 읽는다.**
서로 바꿔 놓아도 말이 되는 주장이 있으면 그 학생의 자료를 다시 읽고 주장을 다시 세운다.
글이 서로 닮는 진짜 원인은 문장 형식이 아니라 **주장이 같기 때문**이다. 이 점검을 하면 첫 문장 형식을
인위적으로 배분할 필요가 없다 — 주장이 다르면 문장은 저절로 갈라진다.

계획은 `students.json`의 `계획` 필드에 저장하고, **주장 목록을 표로 보여주고 승인받은 뒤** 5단계로 간다.
(승인 전에 문장을 쓰지 않는다. 계획이 틀리면 잘 쓴 문장도 버려야 한다.)

**다시 돌릴 때 — 이전 판본의 계획을 복사하지 않는다(필수).** 프롬프트를 고쳤거나 사용자가 재실행을 요청하면
**자료(활동·제약사항)만 담긴 입력을 새로 만든 뒤** 계획부터 다시 세운다. 앞 판본의 `계획`을 옮겨 넣으면
4단계가 실제로 돌지 않은 것이고, 평가문만 바꾼 결과는 재실행이 아니다. 자료를 다시 읽어 같은 주장이 가장 강하면
그대로 확정해도 되지만 **그 판단은 이번에 내린 것이어야 한다.**

## 5단계 — 평가문 작성 (NLP)
**4단계의 계획을 문장으로 옮긴다.** 여기서 새로 재료를 고르지 않는다. 쓰다가 계획이 틀렸다고 판단되면
문장을 밀어붙이지 말고 계획으로 돌아가 고친 뒤 다시 쓴다.

**배치 진행** — "몇 명씩 작성하고 확인할까요?"를 한 번 묻고 그에 맞춘다. 첫 배치는 문체의 기준점이 되므로
승인을 받고 나머지에 같은 기준을 적용한다.

**한 학생 작성 절차** (프롬프트에 단계 지시가 있으면 그것을 우선):
1. 계획의 **주장**을 서론(첫 문장)으로 옮긴다. 첫 문장은 앞으로 무엇을 논할지 밝히는 자리이고 논증은 본론의 몫이므로 근거의 내용을 여기서 미리 말하지 않는다. **이 학생이 어떤 사람인지 규정하며** 시작해 뒤에 무엇이 올지 기대하게 만들고, 강점에는 **교과와 연관된 관심과 그 활동의 가치가 함께** 담기게 한다. **규정하는 말은 학생마다 다르게 잡는다** — 한 어미를 명세에 박아 두면 그대로 복제된다(117명 전원이 같은 종결로 끝난 실측 사례).
2. 계획의 **근거**를 계획한 **순서**대로 서술한다. 근거마다 적어 둔 '왜 뒷받침하는지'가 문장에서 보이게 쓴다.
3. 프롬프트의 문체·어미·금지사항·분량을 지킨다. 학생이 실제로 쓴 **개념명과 기술 용어는 그대로 살리고**, 구현 디테일(변수명·코드 조각·주소)은 쓰지 않는다.
4. **품질 보정 (grammar-checker → humanizer → style-guide)**: ① 맞춤법·띄어쓰기·조사, ② 번역투(에 대해/통해/되어진다)·명사화·획일적 맺음 같은 AI 흔적, ③ 반 전체의 용어·어조 통일(①②는 글마다, ③은 배치 전체를 한 번에). 세특의 명사형 종결·금지 주어·한 문단·분량 규칙이 세 스킬의 권장보다 우선하며 과교정(의미 훼손)은 피한다. 상세는 `references/quality-skills/README.md`.
5. **분량 맞추기**: `byte_count.py`로 재고, 목표를 벗어나면 자르거나 늘리는 게 아니라 **서술을 다듬어 다시 쓴다.**
   ```bash
   python "${CLAUDE_SKILL_DIR}/scripts/byte_count.py" "작성한 평가문"
   ```
6. `students.json`의 `평가문`·`목표바이트`를 채운다.

배치가 끝나면 **바이트와 쉼표를 일괄 검수**한다(둘 다 눈대중 금지).
```bash
python "${CLAUDE_SKILL_DIR}/scripts/byte_count.py" --json results/<연도>_<과목>/<판본>/students.json --write
python "${CLAUDE_SKILL_DIR}/scripts/comma_check.py" --json results/<연도>_<과목>/<판본>/students.json
```
- **`연결어미뒤`와 `가운뎃점`은 0**이어야 한다. 연결어미 뒤 쉼표는 문맥에 맞게 손보거나 `--clean --write`로 정리(원문은 `평가문_초안` 보존), 가운뎃점은 '와/과'·쉼표·풀어쓰기로 바꾼다(자동 정리하지 않는다).
- **`과다`(밀도) 판정은 참고치이지 통과 조건이 아니다.** 셋 이상을 나열하는 목록 쉼표는 정상이며, 밀도를 맞추려고 정상적인 나열을 풀어쓰지 않는다.
- **쉼표를 정리하면 바이트가 줄므로 정리 후 `byte_count.py`로 재검증**한다.

**배치 검토(작성자 자신)** — 배치를 다 쓴 뒤 한 번에 확인한다.
- 각 글이 **계획의 주장을 증명하는가.** 활동 요약으로 흘러간 글은 다시 쓴다.
- 첫 문장만 모아 읽어 서로 닮았는지 본다. 닮았다면 문장이 아니라 **주장**을 다시 본다(4단계 반 전체 점검).
- 절 도입부·맺음 동사가 여러 학생에게 반복되는지 본다(어미는 모두 같으므로 **어휘**를 센다).

그리고 Excel을 갱신한다:
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_workbook.py" results/<연도>_<과목>/<판본>/students.json results/<연도>_<과목>/<판본>/결과.xlsx
```

### 5.5 별도 검토 패스 (독립 서브에이전트 · 사용자 확인 후 실행)
자기가 쓴 컨텍스트 안에서는 자기 글을 승인하기 쉽다. 얕은 grep 린트로 "품질 통과"라 하지 않는다.
- **사용자 확인 게이트**: 토큰·시간이 드므로 **먼저 물어보고** 실행한다. 원하지 않으면 건너뛴다.
- **실행**: `Agent`(general-purpose)로 **검토만**(파일 수정 금지, 지적 목록만 반환) 시킨다. 검토 에이전트는 `grammar-checker`·`humanizer`·`style-guide`를 **`Skill` 도구로 실제 호출**한다(문서만 읽고 눈대중하지 않는다). 프롬프트 템플릿은 `references/quality-skills/review-pass.md`.
- 검토 결과에 `comma_check.py` 측정값을 포함하고 **연결어미 뒤 쉼표는 0**이어야 통과로 본다.
- **반영 — 덮어쓰지 않고 추가한다(필수)**: `평가문`(원본)은 그대로 두고 **`평가문_검토본`**에 담는다(수정할 것이 없는 학생도 검토를 거쳤으면 같은 문장을 넣어 검토 범위를 남긴다). 반영 후 `byte_count.py --json ... --write`로 재검증 → 산출물 재생성.
- **기존 산출물도 덮어쓰지 않는다.** 검토본 업로드 xlsx는 다른 파일명으로 뽑는다(`build_gwagi.py --text`).
- **변경 내역 저장(필수)**: 원문→수정을 `results/<연도>_<과목>/품질수정_변경내역.md`로 남긴다.

## 6단계 — 검수 HTML + 교과세특 업로드 xlsx (+ 결과 JSON)

**(1) 검수용 HTML** — 학생별 평가문을 한 표에서 정렬·검색하며 검수한다.
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_html.py" results/<연도>_<과목>/<판본>/students.json results/<연도>_<과목>/<판본>/결과.html
```
- **표형**: 번호·이름·성적·평가문·바이트·목표·판정(적정/초과/미달)·자료를 한 표에. 열 머리글 클릭 정렬, 상단 검색 필터.
- **근거 대조**: 마지막 열에서 **구성 계획**(주장·근거·순서·제외)과 **활동 자료**를 펼쳐 볼 수 있다 → 주장·근거·글이 맞는지 표 안에서 확인된다. 제약사항은 평가문 칸 아래 경고로 뜬다.
- **복사**: 평가문 칸마다 `복사` 단추가 있어 NEIS 등에 바로 붙여 넣을 수 있다. 활동 자료·계획 블록에도 붙어 있고, 상단 `보이는 평가문 모두 복사`는 화면에 걸러진 학생 전체를 `번호 이름 → 평가문` 형태로 한 번에 복사한다(클립보드 API가 막힌 환경에서는 자동으로 대체 방식으로 복사한다).
- **검토본 대조(5.5를 돌렸을 때)**: `평가문_검토본`이 있으면 원본을 덮지 않고 **두 판본을 나란히** 보여준다. 상단 `보기`로 *나란히 / 원본만 / 검토본만*을 고르고, 달라진 학생에게 `수정` 배지가 붙는다.
- **변경 강조(diff)**: 원본 쪽 **빠진 말**은 취소선, 검토본 쪽 **들어온 말**은 녹색. 어절 단위로 비교하되 짧고 닮은 교체는 글자 단위로 좁혀 한 글자·띄어쓰기 차이도 정확히 보인다. 상단 `변경 강조`·`수정된 학생만` 체크박스로 조절하며, 인쇄 시에는 취소선·밑줄로 나간다.
- `결과.xlsx`도 같은 규약으로 `평가문_검토본`·`바이트수_검토본`·`판정_검토본` 열을 뒤에 덧붙인다(셀 안 변경 강조는 HTML에만 있다).

**(2) 교과세특 업로드 양식 xlsx** — `build_gwagi.py`는 `--template`을 보고 **두 모드를 자동**으로 고른다.

**(2-A) NEIS 채우기 모드 (권장)** — NEIS에서 내려받은 엑셀을 주면 **원본을 보존**하며 세특 칸만 채운다.
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_gwagi.py" results/<연도>_<과목>/<판본>/students.json results/<연도>_<과목>/<판본>/결과_NEIS업로드.xlsx \
  --template "C:/.../2026_1학기_1학년_1_정보_과목세특_1.xlsx"
```
- 매칭 우선순위: **① 반/번호 완전일치 → ② 이름 → ③ (반 없는 양식일 때만) 번호**.
- `번호`는 `10112`·`1/12`·`12` 형식을 모두 인식한다. 별도 `반` 필드가 있으면 우선 사용.
- 실행 후 **매칭 리포트**를 반드시 확인한다(못 찾은 행 / 안 들어간 학생 / 이름 중복 보류).

**(2-B) 새로 만들기 모드** — NEIS 파일이 없을 때. 기본 헤더는 **학번 · 이름 · 교과세특 · 성적**.
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_gwagi.py" results/<연도>_<과목>/<판본>/students.json results/<연도>_<과목>/<판본>/교과기초자료.xlsx \
  --template "${CLAUDE_SKILL_DIR}/assets/교과기초자료_양식.xlsx"
```

**(2-C) 판본 고르기 — `--text`** (두 모드 공통). `auto`(기본)는 검토본 우선, `평가문`/`평가문_검토본`으로 명시할 수 있다. **원본 업로드본을 덮어쓰지 말고** 서로 다른 파일명으로 각각 뽑는다.

**(3) 결과 JSON** — 평가문만 추린 산출물(활동 원자료는 담지 않는다).
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_json.py" results/<연도>_<과목>/<판본>/students.json results/<연도>_<과목>/<판본>/결과.json
```

산출물은 모두 `results/<연도>_<과목>/`에 모여 있다. 위치를 안내하고 마무리한다.

## 과목별 MEMORY 운영
- 시작 시 `references/memory/<과목>.md`(누적 지시)와 `prompts/<과목>.prompt.txt`(맞춤 프롬프트)를 읽어 반영한다.
- **맞춤 프롬프트 관리**: 2단계에서 만든 `prompts/<과목>.prompt.txt`를 재사용하고, 자료 구성·분량 기준이 바뀌면 갱신한다.
- 사용자가 **재사용할 지시**를 주면 `<과목>.md`에 한 줄로 추가하고, 프롬프트에 반영될 성격이면 프롬프트도 고친 뒤 `INDEX.md` 목록을 갱신한다. 무엇을 저장했는지 알린다.
- 일회성 요청은 저장하지 않는다. 규칙은 `references/memory/INDEX.md` 참조.

## 자주 하는 실수 (점검표)
- ❌ **요약한 활동 자료를 근거로 씀** → ✅ `원자료.json`의 **원문**을 읽고 쓴다. 요약본에는 누가 쓴 글인지(인공지능이 대신 쓴 문장)·언제 낸 것인지가 남지 않는다.
- ❌ 계획 없이 문장부터 씀 → ✅ **4단계에서 주장·근거·순서·제외를 먼저 정한다.** 글이 활동 보고로 흘러가는 원인은 대개 여기다.
- ❌ 규칙 통과를 목표로 삼음 → ✅ 목표는 **역량과 그 증명**이다. 규칙은 그것을 돕는 수단이다.
- ❌ 자료에 있는 사실을 다 넣음 → ✅ 주장을 증명하지 않는 사실은 **버린다**(계획의 '제외').
- ❌ 근거를 중요도 순으로 늘어놓아 **활동이 교차함** → ✅ **활동 단위로 묶고** 활동 안에서는 일이 진행된 순서.
- ❌ 첫 문장에 근거를 앞당겨 씀 → ✅ 첫 문장은 **서론**이다. 무엇을 논할지 밝히는 데까지.
- ❌ 첫 문장에 관심만 적거나 한 일만 적음 → ✅ **관심과 활동의 가치를 함께** 담아 어떤 학생인지 규정한다.
- ❌ 판단 술어를 아낀 자리를 비유로 채움(`벽에 부딪힘`·`눈길을 둠`) → ✅ **사실 진술**. 있었던 일을 그대로 적는다.
- ❌ '지엽적 금지'를 넓게 읽어 **학술 개념어까지 지움** → ✅ 금지는 **구현 디테일**(변수명·코드·주소)뿐. 개념명·기전·설계 구조는 탐구의 알맹이다.
- ❌ 근거의 출처를 "수업에서"·"모둠에서"로 뭉뚱그림 → ✅ **활동명 표기**(2단계에서 고정).
- ❌ 분량이 모자라자 **모둠 학생끼리 개념을 나눠 가짐** → ✅ 배분 금지. 덜어낼 것은 **그 학생 안에서** 정한다.
- ❌ 바이트·쉼표를 눈대중 → ✅ `byte_count.py`·`comma_check.py`로 측정(연결어미 뒤 쉼표·가운뎃점 0, 정리 후 바이트 재검증).
- ❌ 문장 수·첫 문장 길이 같은 **수치 상한을 새로 만듦** → ✅ 재는 것은 전체 바이트뿐이다. 지나친 제약이 이상한 문장을 만든다.
- ❌ 보고서 문장 복붙, 코드·변수명 노출 → ✅ 사실만 추출·재서술.
- ❌ 3단계에서 평가문까지 미리 작성 → ✅ 정리 / 계획 / 작성 분리.
- ❌ 산출물을 스킬 폴더에 저장 → ✅ 작업 폴더 `results/<연도>_<과목>/`에 모으기.
- ❌ 검토 결과로 `평가문`을 덮어씀 → ✅ `평가문_검토본`으로 **추가**하고 업로드 xlsx는 `--text`로 판본을 골라 다른 파일명으로.
- ❌ 과목 하나의 요청으로 공용 `scripts/`를 수정 → ✅ 그 과목 폴더에 전용 변형 스크립트를 만들어 적용.
