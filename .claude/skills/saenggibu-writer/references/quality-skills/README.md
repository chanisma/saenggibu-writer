# 품질 보정 스킬 (grammar-checker · humanizer · style-guide) — 세특 파이프라인 통합 가이드

평가문 초안을 **문법적으로 깨끗하고(grammar-checker), 사람이 쓴 듯 자연스럽고(humanizer), 25명 사이 일관되게(style-guide)**
다듬기 위해 세 스킬을 이 스킬 안에 번들로 두고, **4단계(평가문 작성) 안에서** 적용한다.

## 적용 시점과 순서 (4단계 안)
초안 서술 → **① grammar-checker(각 평가문) → ② humanizer(각 평가문) → ③ style-guide(반 전체 일괄)** → 바이트 측정·보정.
바이트는 보정 뒤에 잰다(보정이 길이를 바꾸므로). grammar·humanizer는 글마다, style-guide는 **배치 전체를 한 번에** 본다.

1. **grammar-checker (교정·글마다)**: 맞춤법(되/돼, -ㄴ지/-는지, 안/않), 의존명사 띄어쓰기(수·것·데·바·뿐), 보조용언, 조사(을/를·이/가·은/는), 어미를 바로잡는다. → `grammar-checker/references/`
2. **humanizer (자연화·글마다)**: AI 흔적을 덜어낸다. 세특에서 특히 자주 걸리는 것 —
   - **쉼표 과다**: 빽빽하면 일부를 짧은 문장으로 끊어 리듬을 만든다(인간 글은 문장 길이가 들쭉날쭉).
   - **명사화·`~적 N` 체인**: "분석적 사고와 구성적 사고" 같은 추상 명사 나열을 동사 중심으로 푼다.
   - **번역투**: `~에 대해/~을 통해/되어진다/~에 의해/있어서`를 우리말다운 표현으로.
   - **3박자 리스트·구조 단조로움**: 모두 "A와 B, C를 기준으로" 같은 똑같은 골격으로 찍히지 않게 한다.
3. **style-guide (일관성·반 전체)**: 25명을 **한 묶음**으로 보고 통일한다. 세특에서 핵심 점검 —
   - **용어 통일**: `인공지능`(영문 `AI` 노출 금지), 활동 명칭(`대형언어모델 활동`/`에이전틱 인공지능 활동`/`인공지능 시대 활동`)을 같은 형태로.
   - **어조·종결 일관**: 전원 명사형 종결, "~함/~임/~음" 어미 폭을 고르게.
   - **첫문장·맺음말 분산**: 첫 문장 맺음(돋보임/나타남/엿보임/주목됨/드러남)과 마무리(기대함 계열)가 한쪽으로 쏠리지 않게 다수결이 아니라 **고르게** 편다(획일 = 오히려 비일관으로 본다).
   - **기준어 표기**: "색과 크기, 각도를 기준으로" 같은 골격의 표현·구두점을 학생 간 일관되게.

## 세특 가드레일 (세 스킬의 기본값을 덮어쓰는 최우선 규칙)
세 스킬의 장르 기본값은 `~합니다`(공문서)·`~이다`(학술)다. **세특은 다르다. 아래가 항상 우선한다.**
style-guide는 "사용자 명시 브랜드/프로젝트 가이드 최우선"을 지원하므로, **세특 규칙 = 프로젝트 스타일 가이드**로 못 박는다.

- **종결어미 고정**: 모든 문장은 `~함/~임/~음/~봄/~감/…` **명사형 종결**. 세 스킬이 `~합니다/~이다/~했다`로 바꾸자고 해도 **무시**한다(style-guide의 어조 통일도 이 형태로 수렴).
- **간접인용은 평서종결이 아니다**: `~다고 보다`, `~ㄴ다는 생각`, `닮은/대비됨` 같은 안긴문장은 정상이다. 검증 스크립트의 평서종결 정규식이 `된다고/닮았다는`을 오탐할 수 있으니, **문장의 끝**만 명사형인지 확인한다.
- **금지주어 유지**: "학생은/이 학생"을 humanizer의 "주어 생략 미흡"이나 style-guide의 "주어 일치" 교정이 되살리지 않게 한다.
- **분량 규칙 유지**: 완료(미제출 0) 1450~1500B / 미완료 ≤1500B. 보정으로 미달되면 근거를 더 끌어와 다시 채운다.
- **다수결보다 다양성**: style-guide의 기본은 "다수 표현으로 통일"이지만, 세특의 첫문장·맺음말은 **일부러 분산**한다(25명이 똑같은 문장으로 찍히면 안 됨). 통일 대상은 용어·어조·구두점이고, 분산 대상은 첫문장·맺음말·문장 골격이다.
- **한 문단·부정 표현 금지·코드/변수명 금지**도 그대로.
- **과교정 금지**: humanizer의 변경률 가드(>50% 중단)와 의미 보존 6항(수치·고유명사·인과·부정·인용·핵심주장)을 지킨다. 근거가 바뀌면 안 된다. 이미 자연스럽고 일관되면 그대로 둔다.

## 적용 방식 — 배치에서는 "내재화 + 검수 패스"
학생이 많으면 **학생마다 Skill 도구를 따로 호출하지 않는다.** 대신 위 패턴/규칙을 읽고 **작성·교정에 내재화**한 뒤,
배치가 끝나면 grammar·humanizer는 글별로 점검하고 **style-guide는 반 전체를 한 번에** 훑어 통일·분산을 맞춘다.
단건을 정밀 점검할 때만 글로벌 `grammar-checker`/`humanizer`/`style-guide` Skill을 개별 호출한다.

## 별도 검토 패스 (자기검토 방지)
내재화 보정 + 얕은 grep 린트만으로는 style-guide의 반 전체 쏠림·맞춤법 정밀 오류를 놓치기 쉽다. 배치가 끝나면
**작성한 컨텍스트에서 스스로 승인하지 말고** 독립 서브에이전트(`Agent`)에게 이 세 축 + 위 가드레일로 **검토만** 맡긴 뒤,
돌아온 지적을 저자가 등가·의미보존으로 반영한다. **토큰이 드므로 사용자 확인 후 실행**한다. 프롬프트 템플릿·출력 형식은
→ **`review-pass.md`** 참조. (SKILL.md 4단계의 `4.5 별도 검토 패스`가 이 절차를 호출한다.)

## 검수(정량) 체크
배치 보정 후 다음을 확인한다.
- 규칙: 금지주어·줄바꿈·평서종결·종결어미 = 0 (작업 폴더의 `finalize_*.py` 류 점검)
- 분량: `scripts/byte_count.py --json students.json` (완료 1450~1500, 초과 0)
- humanizer 지표(간이): 평가문당 평균 쉼표(≈3~4개 권장), 번역투 마커 총량(가급적 0~소수)
- style-guide 지표(간이): 영문 `AI` 노출 0, 활동 명칭 표기 통일, 첫문장·맺음말 분포가 한쪽으로 쏠리지 않는지(분산), 기준어 골격 일관
